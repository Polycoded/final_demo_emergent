## Implemented

- Versioned v2 health and runtime state.
- Persisted v2 decision receipts in SQLite.
- Camera policy schema with task, model, mode, priority, schedule, minimum rate, maximum rate, maximum wait and fallback policy.
- SAFETY, PRIORITY, ADAPTIVE and CONTEXTUAL policy resolution.
- Time-zone-aware schedules, including overnight intervals.
- Expiring manual overrides and release API.
- Policy precedence that keeps SAGE/baselines out of protected correctness.
- OpenCV-only cheap observer with motion, frame difference, blur, brightness, contrast, entropy, scene change and history features.
- Central model registry with one warmed resident YOLOX-Tiny ONNX session.
- Model load-event tracking and execution-provider reporting.
- Safety capacity admission against profiled per-model throughput.
- Protected minimum-rate scheduling.
- Deterministic priority, age and observer-utility baseline for adaptive cameras.
- Deterministic camera-ID tie-breaking.
- Central resident-model inference endpoint.
- Three-camera v2 driver that runs cheap observation on every feed and sends only the selected frame to the resident model service.
- WebSocket events for v2 decisions, overrides and resident inference.
- Dashboard camera policy cards, protection state, manual override controls, capacity admission and resident-model state.
- Existing v1 endpoints retained for compatibility.

## Current demonstration policy

| Camera | Mode | Task | Priority | Protected minimum |
|---|---|---|---:|---:|
| A — North Concourse | SAFETY | PERSON | 5 | 0.2 FPS |
| B — East Entry | PRIORITY | PERSON | 4 | — |
| C — Garden Gate | ADAPTIVE | PERSON | 3 | — |

The low protected rate is deliberate for the demo: it proves that protected service is never skipped when due while leaving windows in which adaptive allocation can be observed.

## Evidence boundary

The current v2 scheduler identifies its adaptive score source as:

```text
deterministic-observer-v2-baseline
```

This is not presented as trained task-conditioned SAGE. The Review-1 scalar router remains available through the v1 compatibility path, but its Nano-to-Tiny person-task evidence is not reused as proof of heterogeneous routing.

The remaining research work is:

1. obtain frozen production models and representative data for at least two additional tasks;
2. generate task-normalized production-output-change labels;
3. split by held-out cameras/scenarios;
4. compare motion+age, priority+age, per-task routers and shared task-conditioned SAGE;
5. calibrate confidence on held-out cameras;
6. integrate SAGE only if it materially beats the deterministic baseline.

## Known prototype limitations

- Camera policies are currently process-memory configuration and reset to demo defaults on backend restart.
- One real person detector is resident; PPE, crowd and vehicle services are not falsely simulated as trained production models.
- Capacity throughput is a configured profile and must be replaced by a hardware benchmark before production claims.
- The current scheduler dispatches one selected frame at a time; compatible multi-request batching is not yet connected to the demo driver.
- The dashboard videos and analyzed AVI sources represent the same scenarios but are not frame-synchronized.
- Authentication is demo-local. Production deployment requires unique credentials and a security review.
